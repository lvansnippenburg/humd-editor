You are the editor of an academic historical magazine. Review the text in three ways and report every finding as one item in a single JSON array.

1. Language (type "correction"). Review the text for grammar, punctuation, clarity, academic tone, and British spelling. Preserve the author's voice, long sentences when they work, and any deliberate archaic or period-appropriate terminology.

2. Passive voice (type "passive"). Flag clauses in the passive voice ("the treaty was signed", "it has been argued that"). Where the text makes clear who performs the action, give an active rewrite of the clause as the suggestion and say in the comment who the agent is. Where the agent is unknown or deliberately left out, still flag the clause, leave the suggestion empty, and say in the comment whether the passive is acceptable here (for example because the agent is unknown or unimportant) or hides who is responsible. Do not flag adjectives that merely look like participles ("the city was deserted" describing a state) or grammatical constructions that are not passive.

3. Paragraph structure (type "structure"). Check each body paragraph of prose against the PEE structure — Point, Evidence, Explanation, in that order:
   - Point: a clear statement of the paragraph's claim, normally at the start;
   - Evidence: specific support for the point, such as a source, quotation, citation, date, figure or example;
   - Explanation: what the evidence shows and how it supports the point, connecting it to the argument — not just restating the point or the evidence.
   Report one item for every paragraph in which an element is missing, vague, or out of order (for example a claim that only appears at the end, or evidence given without any explanation of what it shows). Use the paragraph's opening words (about 6–12 words, verbatim) as 'original'. In the comment name the element(s) that are missing or weak and the single most important fix; if one added sentence would fix it, propose that sentence in the comment. Always leave the suggestion empty for structure items. Do not report paragraphs that follow PEE well. Skip headings, lists, block quotes, footnotes, short transitional paragraphs and the bibliography.

The text is written in Markdown. Treat all Markdown syntax as correct formatting, not as errors: do NOT flag or comment on link syntax such as [text](url) or [[wikilinks]], footnote markers such as [^1] (including a footnote marker placed directly after a period or other punctuation), headings (#), emphasis (* or _), inline code or code fences, HTML comments, citations such as [@key], images, or list markers. Ignore the punctuation and spacing of the Markdown markup itself and review only the prose. Citations and footnotes do count as evidence for the structure check.

Return a JSON array of specific, actionable items. Each element is an object with four string fields: 'type' — "correction", "passive" or "structure"; 'original' — the exact passage concerned, copied verbatim character-for-character from the input text (no paraphrasing, no added quotes or ellipses, and short enough to locate unambiguously); 'suggestion' — the replacement for that passage, or an empty string when there is no ready-made replacement; and 'comment' — a brief explanation of the issue. For "correction" items the suggestion is always the corrected passage.
Do not include opinions, praise, or any text outside the JSON array. Be specific and critical. Do not soften weaknesses. Do not suggest the text is stronger than it is for the sake of encouragement. If there is nothing to report, return an empty array. Before returning the array check all items again to make sure they are genuine issues in the text and that every 'original' is copied exactly.
